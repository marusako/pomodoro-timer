# Kugiri Timer

Electron で作った Windows 向けの作業タイマーです。作業と休憩を区切ってくり返し、集中力を保てます。カレンダーと時間割で予定を管理でき、壁紙と BGM で落ち着いて作業できる画面にできます。

2026 年 10 月に「Pomodoro Timer」から名前を変えました（「Pomodoro」は商標の持ち主のガイドラインで、許可なくアプリ名に使うことが認められていないため）。

## 機能

### タイマー

- 作業 → 短い休憩 → 作業 … を自動で切り替え、決まった回数ごとに長い休憩を入れる
- 作業・休憩が終わったとき、またはスキップしたときは、次のセッションが自動で始まる（止めるときは一時停止）
- スタート / 一時停止 / リセット / スキップ（Space キーでスタートと一時停止）
- 円形のプログレス表示と、モードごとの色分け。タイマーの下に今の時刻を小さく出す
- 作業・休憩の時間と、長い休憩までの回数を、iPhone のタイマーのようなホイールで設定（マウスホイール・矢印キー・クリックでも操作可能）。メイン画面の右上のタイマーのボタンから開く
- タイマーのプリセット：定番（25/5/15 分・4 回）・長め（50/10/30 分・2 回）から選べるほか、今の設定に名前を付けて 10 個まで保存できる
- 設定の変更はすぐに反映・保存される。始めたセッションの進み具合は消さず、新しい時間は次のセッションから使う
- 今日の作業完了回数の記録（日付が変わると 0 に戻る）。メイン画面の Today / Round の行は、General タブで表示・非表示を切り替えられる（隠していても記録は続く）

### カレンダーと時間割

- カレンダー：右上のカレンダーのボタンで開く。月のカレンダーで日を選ぶと、その日の予定が 1 つの一覧に並び、その場で追加・編集・削除できる
- 予定のくり返し：この日だけ / 毎日 / 平日（月〜金） / 毎月〇日 / 毎週〇曜日（毎週は「時間割」のコマになる）。くり返す予定は終わりの日を決められ、「この日だけ休む」もできる
- 時間割の入力の補助：開始時刻・1 コマの長さ・休み・長い休み（昼休みなど）・コマ数から「1限」「2限」… をまとめて作る、ほかの曜日にコピー、この日 / この曜日をすべて消す
- 予定（カレンダーの予定と毎週のコマ）の開始時刻に通知し、タイマーが止まっていれば作業の頭に準備する（スタートは自分で押す）。予定にプリセットを選んでいればその時間で、毎週のコマは今の設定のまま。終了時刻にも通知する
- 予定の 1・3・5・10 分前に知らせることもできる（カレンダーのタブの一番下で選ぶ）
- 外部カレンダー：Google カレンダーなどの「iCal 形式の非公開 URL」を 5 つまで登録して、予定を読み取り専用で取り込める（起動したとき・30 分ごと・「今すぐ更新」で読み直す）。取り込んだ予定も、自分の予定と同じく知らせ・タイマーの準備・次の予定・集中の記録に使う。終日の予定は一覧に出すだけ。URL はこの PC の中で暗号化して保存し、書き出しのファイルには入れない
- メイン画面に、今やっている予定か次の予定（毎週のコマも含む）を 1 行出す（押すとカレンダーを開く）
- 予定ごとの集中の記録：作業を数えた分数と、最後まで終えた作業の回数を、その時刻の予定ごとに残す（3 か月分）。カレンダーの一覧で「集中 50 分・2 回」のように見られる
- 記録の画面：カレンダーの「記録」タブで、週（月曜始まり）・月ごとの集中の合計と回数、日ごとの棒グラフ（縦軸付き）、前の週・月との差を見られる。合計には、予定がない時間の作業も入る。一番下に、記録のしかた（何を・いつ数えるか）の説明がある
- 予定の通知は、アプリが起動している間だけ出る

### 見た目

- ウィンドウの大きさに合わせて、タイマー全体（文字も含む）が拡大・縮小する。全画面では画面に収まる範囲で大きくなり、幅を狭めてもボタンの文字は改行しない
- テーマの切り替え（Auto / Light / Dark。Auto は Windows の設定に合わせる）
- 壁紙（デフォルト 5 種類：Dawn / Ocean / Forest / Night / Paper、画像の取り込みも可能）。壁紙があるときは、タイマー部分をすりガラスのカードにして読みやすくする。カードの不透明度は Appearance タブで 0〜100% に調整できる。カードを薄くすると、文字のまわりにうっすら影が付き、壁紙の上でも読みやすくなる
- タイマーの数字のフォントを、Windows に入っている 6 種類から選べる（標準・細字・極太・角ばった字・等幅・明朝風）
- 全画面表示（右上のボタンか F11 キーで切り替え、Esc でも抜けられる）

### 音

- BGM：取り込んだ曲（MP3 / WAV / OGG / M4A）と、ノイズ（White / Pink / Brown Noise）・環境音（雨・波・風・焚き火・心音。どれもアプリの中で作る音で、音声ファイルは使わない）
- BGM を選んでいるときは、画面の下に再生バーが出る（前へ・▶ / ⏸・次へ、曲名、再生位置、リピート（オフ / 全曲 / 1 曲）、シャッフル、音量）。再生リストの小窓で曲を選ぶ・並べ替える（ドラッグか Alt + ↑ / ↓）・ノイズに切り替えることができる
- 自分のプレイリストを 10 個まで作れる（「全曲」と切り替えて使う）
- 再生のルール：取り込んだ曲は ▶ / ⏸ を押したときだけ再生・停止する（休憩中も流れ続ける）。ノイズは ▶ / ⏸ に加えて、作業が始まると流れ、休憩になると止まる。起動したときはどちらも止まっている
- キーボードのメディアキーと、Windows の再生操作（Media Session）で操作できる。曲名と再生状態も Windows に表示される
- 音量は Alarm（終了時のチャイム）・BGM・SE（ボタンの操作音）の 3 つに分けて調整でき、それぞれ Test で試聴できる。Master の音量で、3 つをまとめて上げ下げできる（実際の音量は「Master × それぞれの音量」）
- アラームの音は Chime / Bell / Digital / Marimba の 4 種類、SE（ボタンの操作音）は Pop / Click / Wood / Soft の 4 種類から選べる（選ぶとその場で試聴できる）
- Sound タブの「初期化」ボタンで、音量とアラーム・SE の音を初期値に戻せる（確認あり。BGM の選択はそのまま）

### そのほか

- 設定は画面全体に重なるパネルで、Sound / Appearance / General のタブに分かれている
- Esc・何もないところのクリック・右クリックで、メイン画面に向かって 1 つ戻る（設定パネル → 再生バーの小窓の順に閉じる）
- 多言語対応：日本語、English、한국어 から General タブで選べる。初めて起動したときは Windows の言語に合わせる（日本語なら「日本語」、韓国語なら「한국어」、それ以外は「English」）
- デスクトップ通知。通知を押すと、アプリのウィンドウが前に出る（最小化していれば元に戻す）
- 保存データの書き出し・読み込み（General タブ。1 つの JSON ファイルにまとめる。取り込んだ曲と壁紙のファイルは含まない）
- 一般タブにクレジット（作者・開発協力・Pomodoro Technique® の商標について）
- 多重起動の防止（2 つ目を起動すると、開いているウィンドウが前面に出る）
- 自動アップデート（起動時に新しいバージョンを確認し、「更新する」を押すとダウンロードして更新）

| 設定 | 初期値 | 範囲 |
|---|---|---|
| 作業 | 25 分 | 1〜120 分 |
| 短い休憩 | 5 分 | 1〜60 分 |
| 長い休憩 | 15 分 | 1〜120 分 |
| 長い休憩までの回数 | 4 回 | 2〜10 回 |
| 音量（Master / Alarm / BGM / SE） | 100 / 60 / 40 / 40 | 0〜100（0 は消音） |
| アラームの音 | Chime | Chime / Bell / Digital / Marimba |
| SE の音 | Pop | Pop / Click / Wood / Soft |
| テーマ | Auto | Auto / Light / Dark |
| 壁紙 | なし | なし / デフォルト 5 種類 / 取り込んだ画像 |
| カードの不透明度 | 72% | 0〜100%（0 は完全に透明。壁紙があるときだけ使える） |
| タイマーの数字のフォント | 標準 | 標準 / 細字 / 極太 / 角ばった字 / 等幅 / 明朝風 |
| BGM | なし | なし / White・Pink・Brown Noise / 雨・波・風・焚き火・心音 / 取り込んだ音声 |
| 予定の前に知らせる | しない | しない / 1・3・5・10 分前 |
| 予定・時間割のコマ | — | 予定は 500 件、コマは 200 個まで。名前は 40 文字まで。日をまたぐ予定は作れない |

取り込める形式は、壁紙が PNG・JPEG・WebP・GIF、BGM が MP3・WAV・OGG・M4A です。取り込んだファイルはアプリの保存フォルダーにコピーされるので、元のファイルを移動・削除しても使い続けられます。アプリから削除しても、元のファイルは消えません。

## 必要なもの

- Node.js 22 以降（テストのスクリプトがファイル指定にグロブパターンを使うため）
- Windows（exe のビルドは Windows 向けのみ設定済み）

## 使い方

```bash
npm install
```

```bash
npm start
```

### テスト

タイマーや設定、アップデート案内の状態遷移などのロジックを、Node.js 標準の `node:test` で検証します。あわせて、全ソースファイルの構文エラーも検査します。

```bash
npm test
```

GitHub に push すると、GitHub Actions（`.github/workflows/test.yml`）でも同じテストが自動で実行されます。

### exe のビルド（手元での確認用）

```bash
npm run dist
```

`dist/<version>/`（例：`dist/1.1.0/`）に次のファイルが作られます。バージョンは `package.json` の `version` で決まり、バージョンごとに別のフォルダーに分かれます。手元のビルドは GitHub にはアップロードされません。

| ファイル | 内容 |
|---|---|
| `kugiri-timer-Setup-<version>.exe` | インストーラー。ユーザー単位で `%LOCALAPPDATA%\Programs` にインストールされ、管理者権限は不要 |
| `latest.yml` | 自動アップデート用の情報（最新バージョンと、ファイルのハッシュ） |
| `kugiri-timer-Setup-<version>.exe.blockmap` | 自動アップデートの差分ダウンロード用 |

exe はコード署名をしていないため、初回起動時に Windows SmartScreen の警告が出ることがあります。「詳細情報」→「実行」で起動できます。

### リリース（自動アップデートの配信）

`v` で始まるタグを push すると、GitHub Actions（`.github/workflows/release.yml`）が次の処理を自動で行います。

1. テストを実行する
2. タグと `package.json` の `version` が一致しているか確認する（ずれていたら止める）
3. `release-notes/<タグ>.md` から Release のタイトルと説明文を取り出す（ファイルがない・空なら止める）
4. Windows 用にビルドし、GitHub Release に exe・`latest.yml`・blockmap を公開する（タイトルと説明文も入る）

インストール済みのアプリは、起動時にこの Release の `latest.yml` を読み、新しいバージョンがあれば更新を案内します。

リリースの手順：

1. `package.json` の `version` を新しい番号に変える
2. `release-notes/v<番号>.md` を作る。1 行目に `# タイトル`、その後に説明文（Markdown）を書く
3. この 2 つをコミットして push する
4. タグを付けて push する

```bash
git tag -a v1.2.0 -m "v1.2.0"
```

```bash
git push origin v1.2.0
```

説明文のファイルは、手元でも次のコマンドで確認できます（タイトルが表示され、説明文が指定したファイルに書き出されます）。

```bash
node scripts/release-notes.mjs v1.2.0 release-body.md
```

自動アップデートは、リポジトリが公開（Public）されている必要があります。非公開のままだと、アプリから Release を読めないため、更新の確認は失敗します（エラーは画面に出さず、ログに残すだけです）。

アイコンは `build/icon.png`（256×256 以上）を差し替えてから、再度ビルドすると変更できます。

## 設計メモ

- **残り時間は終了予定時刻から計算する**：スタート時に終了予定時刻を決め、毎回「終了予定時刻 − 現在時刻」で残りを求めます。`setInterval` の呼び出しが遅れても、誤差が積み重なりません。
- **ロジックと画面の分離**：`src/timer.js` は状態を書き換えず、新しい状態を返す関数だけで構成しています。そのため、Electron を起動しなくてもテストできます。
- **セキュリティ**：レンダラーは `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true` で動かし、Node.js の機能を使えないようにしています。さらに、Content Security Policy で外部のスクリプトとスタイルの読み込みを禁止しています。
- **取り込んだファイルの読み込み**：画面からは専用の読み込み口 `app-media://<種類>/<保存名>` だけで読みます。保存名はアプリが付けたランダムな名前（英数字とハイフン + 許可された拡張子）に限り、`../` などで保存フォルダーの外を読めないようにしています。
- **自動開始の基準時刻**：次のセッションは「前の終了予定時刻」ではなく「終了を検知した時刻」から数えます。スリープ明けなどで更新が遅れても、何回分もまとめて完了扱いになりません。
- **ホイールの値の確定**：マウスホイール・矢印キー・クリックでは行き先が分かっているので、スクロールの完了を待たずにすぐ確定します。指やマウスでつかんで動かしたときだけ、スクロールが止まった位置で確定します（それ以外のスクロールは見た目のためだけのもので、途中で止まっても値を決め直しません）。マウスホイールは 1 目盛りで 1 つずつ動かします。
- **保存先**：設定・完了回数・予定・時間割・集中の記録は保存フォルダーの `data.json` に、取り込んだ壁紙・BGM は `media\` に保存します。保存フォルダーは、ビルド版が `%APPDATA%\kugiri-timer`、開発版（`npm start`）が `%APPDATA%\kugiri-timer-dev` です。開発中に試した設定が、普段使うアプリに混ざらないよう分けています。
- **data.json の書き方**：読み書きはメインプロセス（`data-store.js`）が行います。画面は起動時に 1 回だけ全部を読み、変えたら項目ごとに知らせます。書き込みは 0.5 秒まとめてから `data.json.tmp` に書き、それを `data.json` に差し替えるので、書いている途中で電源が切れても元のファイルは壊れません。読めない `data.json` は、上書きする前に別の名前で残します。v2.4 以前は `localStorage` に保存していたため、`data.json` がないときは `localStorage` の中身を写します（`localStorage` は消さずに残します）。ブラウザーで画面だけを開いたとき（プレビュー）は、今までどおり `localStorage` を使います。
- **外部カレンダー**：Google の API とログイン（OAuth）は使わず、カレンダーの「iCal 形式の非公開 URL」から .ics を読みます。そのため、API の利用規約・開発者登録・審査が要りません。URL を知っている人は誰でも予定を読めるので、URL は Electron の `safeStorage`（Windows の暗号化の仕組み）で暗号化して `feeds.json` に保存し、画面には戻しません。通信はメインプロセスで行い、画面の Content Security Policy（外との通信の禁止）はそのままです。.ics の読み取りには [ical.js](https://github.com/kewisch/ical.js)（MPL-2.0）を手を加えずに使っています。
- **名前の変更と引き継ぎ**：「Pomodoro Timer」から「Kugiri Timer」に名前を変えたため、保存フォルダーも `pomodoro-timer` から `kugiri-timer` に変わりました。新しい版を初めて起動したとき、新しいフォルダーにまだ設定がなければ、古いフォルダーから設定・記録（`Local Storage`）と取り込んだファイル（`media`）をコピーします（`legacy-data.js`）。古いフォルダーは予備として残します。アプリの識別子（`build.appId` の `io.github.marusako.pomodoro-timer`）は変えていません。変えるとインストーラーが別のアプリとして扱い、自動アップデートで二重にインストールされるためです。
- **音の生成**：Alarm・SE・ノイズは Web Audio API でその場で作るため、音声ファイルを同梱していません。アラームと SE の音は「楽譜のデータ」（`src/alarms.js`・`src/se-sounds.js`）と「鳴らす処理」（`src/sound.js`）に分けているので、音の長さや重なったときの大きさを、音を鳴らさずにテストできます。
- **画面サイズに合わせた拡大**：メイン画面の大きさは、CSS の変数 `--u`（標準のウィンドウでの 1px が、今の画面で何 px になるか）を掛けて決めています。`--u` は「幅 ÷ 410」と「高さ ÷ 600」の小さいほうなので、縦長でも横長でも画面からはみ出しません。基準の幅 410 は、いちばん幅を取るボタンの並び（韓国語の「일시정지」表示時）が、幅 320px（小さめのスマホ）まで 1 行に収まるように決めています。JavaScript を使わず CSS だけで計算するため、ウィンドウの大きさを変えるとすぐに反映されます。
- **全画面表示のキー**：F11 は、画面やメニューに届く前にメインプロセスで受け取ります（`before-input-event`）。Electron の標準メニューにも F11 の操作があるため、そこで止めて二重に切り替わらないようにしています。Esc は「設定パネルを閉じる」にも使うので、パネルの状態が分かる画面側で受け取ります。
- **多重起動の防止**：同じ保存先を 2 つのウィンドウで同時に使うと、後から起動した側が設定や記録を読み書きできなくなります。そのため、2 つ目の起動は終了させています。
- **自動アップデート**：[electron-updater](https://www.electron.build/docs/features/auto-update) を使います。利用者が「更新する」を押すまでダウンロードせず、ダウンロード後に再起動しなかった場合は、アプリの終了時に更新します。再起動するとタイマーが止まるため、タイマーが動いているときは確認を出します。
- **配布ファイル名にスペースを入れない**：Release にアップロードしたファイル名が書き換えられると、`latest.yml` に書かれた名前とずれて更新が失敗します。スペースを含む名前はその原因になりやすいため、exe の名前はハイフンでつないでいます。
